## 1. Что сделано

В страницу паспорта вина добавлено пятое состояние — информационный экран, который
показывается, когда API сообщает, что вино временно ограничено. Адресная схема страницы
не менялась: это по-прежнему `wine-passport.html?wineId=...`, постоянный адрес и QR
сохраняются. Это не удаление, не блокировка и не возврат в черновик.

Изменённые файлы (три):

| Файл | Что изменено |
|---|---|
| `wine-passport.html` | Новая функция `renderUnavailable()`; порядок решения в `load()`; два CSS-класса `.state-lead` / `.state-note` |
| `src/i18n/cap-i18n.js` | Вставлены 4 новых ключа в каждый из 12 языковых блоков (48 строк текста) |
| `docs/CAP-PASSPORT-TEMPORARILY-UNAVAILABLE-S4C-01.md` | Этот отчёт |

## 2. Контракт API (зафиксирован ведущим, реализуется параллельно на бэкенде)

`GET /api/cap/wines/:wineId`

| Случай | Ответ | Что рисует страница |
|---|---|---|
| вино доступно | `200 { wine, vintages }` | паспорт, как раньше |
| вино ограничено | `200 { "wine": null, "vintages": [], "availability": "temporarily_unavailable" }` | информационный экран |
| неизвестное вино | `404` | «не найдено», как раньше |

Новых полей не придумано: страница читает ровно поле `availability` и ровно значение
`temporarily_unavailable`.

## 3. Порядок решения в `load()` — дословно

Файл `wine-passport.html`, строки 295-298:

```js
  if (data && data.availability === 'temporarily_unavailable') { renderUnavailable(); return; }
  if (!data || !data.wine) { renderNotFound(); return; }
  renderPassport(data.wine, data.vintages || []);
}
```

Проверка «временно ограничено» стоит ПЕРЕД проверкой наличия `wine`. Поэтому пустое
`wine` при выставленном флаге уходит на информационный экран, а не в «не найдено».

Ветки выше по функции не тронуты: нет `wineId` → «не найдено»; `404`/`400` → «не найдено»;
прочий не-ok → «ошибка»; сеть упала → «ошибка» (`wine-passport.html:283-294`).

Побочно закрыта дыра, существовавшая до правки: строка `if (!data || !data.wine)` раньше
отсутствовала, и ответ с `wine: null` ронял страницу. См. раздел 6.

## 4. Текст экрана

Слова владельца воспроизведены полностью. Русская версия:

```
ПАСПОРТ ОБНОВЛЯЕТСЯ
Информация об этом вине временно обновляется.
Пожалуйста, попробуйте открыть паспорт позже.
Мы уточняем некоторые сведения, чтобы предоставить вам наиболее актуальную
информацию. Паспорт снова станет доступен после завершения обновления.
```

Обязательная короткая версия («Информация об этом вине временно обновляется.
Пожалуйста, попробуйте открыть паспорт позже.») — это заголовок и первая строка тела.
Расширенный пример владельца стоит ниже, более тихим шрифтом.

Подпись `Tasting & Toasting` второй раз не добавлена: она уже есть в шапке страницы
(`wine-passport.html:94`), шапка видна на этом экране — проверено на снимке.
Полная форма `Tasting & Toasting CAP` стоит в заголовке вкладки (`wine-passport.html:6`).

Запрещённые слова: автоматическая проверка видимого текста на всех 12 языках
(`verified`, `blockchain`, `on-chain`, `immutable`, `подтвержд`, `удал`, `снят`,
`черновик`, `заблокир`, `ошибк`, `error`) — ноль совпадений.

## 5. Четыре языка и остальные восемь

Переводы добавлены штатным механизмом — таблицами в `src/i18n/cap-i18n.js`, тем же,
которым переводится вся страница. Хардкода на одном языке нет.

Новые ключи: `wn_un_kick`, `wn_un_title`, `wn_un_body`, `wn_un_note` — в каждом из 12
языковых блоков: en, fr, ru, es, uk, it, de, he, pt, ka, ro, pl.

ОТДЕЛЬНАЯ НАХОДКА, НЕ ИСПРАВЛЯЛАСЬ. До этой правки все ключи экранов состояний
(`wn_*`) существовали ТОЛЬКО в английском блоке: в блоке `en` их 17, во всех остальных
11 блоках — 0. Из-за отката на английский (`cap-i18n.js:354-357`) экраны «не найдено» и
«ошибка» на странице паспорта вина сегодня показываются по-английски во всех языках.
Это видно в разделе 6, случай 3: при `lang=ru` текст «WINE NOT FOUND / This wine couldn't
be found.» Новый информационный экран этой болезнью не страдает — он переведён на все 12.
Доделывать чужие экраны в этой задаче не стал: вне границ, расширяет диф.

## 6. Проверка в настоящем браузере

Боевой бэкенд ограниченного вина пока не отдаёт, поэтому проверка велась на подставленном
ответе: локальный http-сервер отдаёт страницу и три разных тела по адресу
`/api/cap/wines/<id>`, страница запускается с параметром `api`, который она уже
поддерживает (`wine-passport.html:122`). Браузер — Chromium через Playwright.

ОГОВОРКА ЧЕСТНОСТИ: браузер, доступный на машине владельца, до этого сервера не достаёт —
у рабочей Linux-VM нет сетевого интерфейса, кроме loopback, и панель браузера хоста в неё
не ходит. Проверка выполнена настоящим Chromium в облачном контейнере на тех же двух
файлах, снятых с рабочего дерева. Это настоящий браузер и настоящий рендер, но не браузер
владельца.

То есть без этой правки посетитель получил бы пустую страницу и сломанный скрипт — даже
не «не найдено». После правки — информационный экран, консоль пустая.

## 7. Вид

Экран собран на уже существующих в файле приёмах: контейнер `.state-screen`, кружок
`.state-icon`, кикер `.state-kick`, заголовок `.state-title`, тело `.state-body` — те же,
что у `renderNotFound()`. Цвета взяты из переменных `:root`: `--gold-soft` для знака,
`--gold-dim` для кикера, `--cream` для заголовка.

Признаков ошибки нет: красный `--err` не используется, слова «ошибка» нет, кнопки
«попробовать снова» нет. Знак в кружке — многоточие «…», спокойное, не циклическая стрелка.

Кнопка не добавлена сознательно. Перезагрузка сейчас ничего не изменит — вино ограничено
на стороне сервера, и повторный запрос вернёт тот же ответ. Текст владельца просит
посетителя вернуться позже, а не нажимать. Добавлены только два CSS-класса:
`.state-lead` (отступ между обязательной короткой фразой и пояснением) и
`.state-note` (пояснение тише основного текста).

## 8. Что осталось UNKNOWN

1. Отдаёт ли боевой бэкенд поле `availability` — на 11.10.2026 нет: в репозитории
   tt-landing строка `temporarily_unavailable` не встречается нигде, кроме этой правки.
   Задача на бэкенд выполняется параллельно, её результат здесь не проверялся.
2. CORS на боевом домене. Ведущий проверил живьём, что страница сегодня не может прочитать
   данные с `tt-stack-prod.onrender.com` — домен сайта не разрешён. Это настройка боевого
   окружения, она владельческая и в эту задачу не входила. Пока она не снята, любой экран
   этой страницы в бою пойдёт по ветке «ошибка», а не по новой.
3. Поведение в браузере владельца не проверялось — причина в разделе 6.
