### Отозванный код (новое поведение)

При `bottle.status = 'void'` паспорт не показывается вообще: приглушённый силуэт
и объяснение, что производитель отозвал код. Это не «не найдено» — запись
существует. Единственный статусный шлюз: `'minted' | 'claimed' | 'active' |
'activated'` получают полный документ. Так же устроен утверждённый экран
приложения (`bottle.tsx:151-186`, `isRevoked`). До этой правки сайт показывал
полный паспорт по отозванному коду.

### Текст «не найдено» больше не обещает проверку

Было: «We couldn't verify this bottle.» Стало: «We couldn't confirm this. This
code isn't in our records.» — дословно как в канонном шаблоне
(`BottleScan.dc.html`, блок `is404`) и в утверждённом экране приложения.

## 5. Запросы, адреса, права — не менялись

| Страница | Запрос | Параметры |
|---|---|---|
| `bottle-scan.html` | `GET {API}/scan/{token}` | `?token=` |
| `winery-passport.html` | `GET {API}/wineries/{slug}` + необязательный `GET {API}/wineries/{slug}/wines` | `?slug=` |
| `vintage-passport.html` | `GET {API}/vintages/{vintageId}` | `?vintageId=`, необязательный `?winerySlug=` |

Ни один запрос, параметр и публичный адрес не изменены. Второй запрос на
странице винодельни остался необязательным: при его отказе паспорт
показывается полностью, только без полосы вин.

Переходы ведут туда же, куда раньше:
`bottle-scan.html?token=`, `wine-passport.html?wineId=&winerySlug=`,
`winery-passport.html?slug=`, `vintage-passport.html?vintageId=`.

**Одно отличие в переходах:** мои три страницы переносят не только `?lang=`, но
и `?api=`. Эталон `wine-passport.html` переносит только `?lang=` — это стоит
учесть при сквозной проверке в тестовой среде: переход с паспорта вина на
соседний теряет `?api=`. Сам паспорт вина я не трогал.

## 6. Проверка данных: ни одного выдуманного поля

Каждое выводимое значение сверено с кодом сервера
(`tt-stack api/src/routes/cap.ts`):

- `GET /api/cap/scan/:qrToken` (строки 933-985) отдаёт `winery` (включая
  `locality`, `region`, `country`, `founded_year`, `tagline`, `description`,
  `website_url`), `dna`, `wine`, `vintage` (`abv`, `grape_composition`,
  `bottles_produced`, `release_date`, `production_notes`, `tasting_notes`),
  `bottle` (`qr_token`, `bottle_number`, `total_in_series`, `status`,
  `scan_count`), `timeline`.
- `GET /api/cap/wineries/:slug` (646-670) + `loadWineryBySlug` (577),
  `loadWineryDna` (590), `loadWineryServices` (603).
- `GET /api/cap/wineries/:slug/wines` → `loadWineryWines` (614) — **включает
  `hero_image_url`**, поэтому фотография на карточке вина законна.
- `GET /api/cap/vintages/:vintageId` (740-765) — **включает `ean_upc` и
  `bottle_image_url`**, поэтому EAN и фотография бутылки законны.

Пустое поле прячет свою строку или свою полосу; заглушек вместо данных нет.

**Ничего бутылочного на остальных паспортах.** Поиск по
`winery-passport.html` и `vintage-passport.html` на `qr_token`,
`bottle_number`, `scan_count`, `total_in_series`, `timeline` даёт **0**
вхождений в каждом файле.

## 9. Найдено вне моих границ — названо, не тронуто

1. **`wine-passport.html` проверяет поле, которого сервер не отдаёт.** Строка
   295: `if (data && data.availability === 'temporarily_unavailable')`. Поиск
   `grep -rn "availability" api/src/routes/cap.ts` в tt-stack даёт только
   комментарий о календаре (строка 2056); `temporarily_unavailable` в
   `api/src` не встречается вовсе. То есть экран «паспорт обновляется»
   недостижим через нынешний прод-API. Ветка безвредна, но владелец может
   считать, что эта функция работает. Паспорт вина утверждён — я его не
   трогал.

2. **37 ключей словаря остались только в английском.** Ни один из них не
   запрашивается четырьмя паспортами (проверено скриптом). Это остатки прежних
   реализаций, включая весь словарь статусов проверки (`vs_verified`,
   `wp_vs_prefix`, `wp_verified_winery`), который теперь сознательно не
   используется. Исключение: `nf_token_missing` используется
   `cap-qr-sticker.html` — файл вне моих границ. Удаление остальных — решение
   ведущего, я их не удалял.

3. **`is_first_registered_in_country` не выводится.** Поле есть в `dna`
   (`loadWineryDna`, `tt-stack api/src/routes/cap.ts:593`) и утверждённый экран
   приложения показывает по нему отдельный бейдж. На сайте такого бейджа не
   было, и задача его не поручала — не добавлял. Ключ `first_registered` в
   словаре жёстко привязан к Польше («First registered vineyard in Poland»), то
   есть для бейджа с подстановкой страны он не годится.

- **Ответы живого API.** Поля сверены с исходным кодом маршрутов в tt-stack, а
  не с ответом прод-сервера.
- **Push.** В этой VM нет учётных данных GitHub; ветка не отправлена, PR не
  открывался, деплоя не было.
