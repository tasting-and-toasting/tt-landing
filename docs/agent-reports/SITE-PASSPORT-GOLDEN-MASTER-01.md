# SITE-PASSPORT-GOLDEN-MASTER-01 · публичный паспорт вина по Golden Master

REPO: tt-landing · BRANCH: `SITE-PASSPORT-GOLDEN-MASTER-01` · DATE: 14.11.2026 · TO: T&T NEXT
Эталон: `tt-passport-factory/templates/golden-master.html` и превью `out/previews/*.html` (4 новые с ветки `PASSPORTS-4-LABELS-01`, 334eaac). Фабрика не менялась.

## Что было

- В шапке у `wine-passport`, `vintage-passport`, `winery-passport` и `bottle-scan` стоял текст «CAP». Логотипа не было.
- На странице вина были: герой, список карточек урожаев, адрес/страна, статус проверки. Блоков урожая (крепость, заметки, дегустация), винодельни, провенанса, кнопок и demo-блоков не было.
- Ветки `feature/site-etalon-wine-01`, `-winery-01`, `-bottle-01` уже слиты в main (PR #29, #30, #31, плюс #32). Эта работа сделана поверх них: фото с подписью источника, силуэт, лайтбокс, 12 языков, состояния «не найдено» и «черновик» взяты как есть, с нуля ничего не переписывалось.

## Что сделано

**Шапка, все 4 страницы** (`src/passport/tt-head.css`, `src/passport/tt-head.js`, `assets/tt-logo.svg`):
- слева кнопка «назад» и логотип Tasting & Toasting. Это тот же SVG, что в golden-master.html (`viewBox 0 0 387 60`, цвет `#f5efe3`), вынесен в файл. Логотип ведёт на `/`;
- справа крошки «винодельня / вино / урожай», дальше 12 флажков. На ширине ≤1180 флажки уходят на отдельную строку, на ≤640 крошки тоже, поэтому логотип не перекрывается (это проверяется скриптом);
- кнопка «назад» делает `history.back()`, если пришли с этого сайта, иначе открывает `/`. Подпись кнопки на 12 языках;
- RTL: в иврите шапка зеркалится, шеврон тоже.

**Страница вина** (`wine-passport.html`), блоки в порядке GM:
1. Слева: фото бутылки целиком, под ним «Источник: домен», под ними метка «Research Edition».
2. Справа: «Вино», название, год золотом (только если у вина ровно один урожай с годом), метки цвета и сладости, строка стиля в рамке, описание, «от <винодельня> →».
3. Урожай: «Урожай {год}», крепость, `vintage.production_notes`, цитата из `vintage.tasting_notes`. Если урожаев несколько, рисуется блок на каждый, свежие сверху.
4. Винодельня: название (ссылка на паспорт винодельни), «местность · регион · страна» с флагом, метка «Research Edition · собрано T&T», сайт.
5. «Происхождение · путь этой бутылки». У API вина нет событий, поэтому всегда честный пустой текст из GM.
6. Кнопки «{год} · Открыть урожай», «Открыть вино», «Открыть винодельню», «Поделиться» (`navigator.share`, иначе ссылка копируется в буфер с подписью «Ссылка скопирована»).
7. «Скоро»: «Купить эту бутылку» и «Найти дегустацию рядом» с пометкой `demo`, как в GM. Кнопки неактивны, никуда не ведут.

Новые строки на 12 языках (`GM_I18N` в `wine-passport.html`). Русский текст взят из превью GM дословно.

**Откуда данные.** Только `GET /api/cap/wines/:id` и `GET /api/cap/wineries/:slug`. Второй запрос нужен для региона, сайта и `verification_status` винодельни, потому что в ответе вина этих полей нет. API не менялся. Если поля нет, строка или блок не рисуется. Крепость `"12.00"` выводится как `12%`: это форматирование числа, значение не меняется.

**Метка Research Edition** показывается, только когда у винодельни в API `verification_status` есть и он не `verified`/`certified`. Сейчас у всех шести виноделен `claimed`, поэтому метка видна.

**Винодельня.** ДНК (семья, земля, философия, история) уже выводилась при наличии полей (`dnaBlock`, `winery-passport.html`). У La Chablisienne приходят земля, философия и история, они на странице. Семьи в API нет, её блока нет. Поменялась только шапка.

**Урожай и бутылка.** Поменялась только шапка.

## Убрано со страницы вина (в GM этого нет)

Отдельные строки сортов и апелласьона, `story_text` цитатой, бейдж статуса проверки, строки страна/адрес/местность (страна теперь в блоке винодельни), сетка карточек урожаев (вместо неё блоки урожая). У шести проверенных вин сорта и апелласьон всё равно есть внутри строки стиля. **Решение за владельцем:** у вина без `style` сорта и апелласьон теперь не видны. Если их нужно вернуть, это одна строка в герое.

## Проверка

Сервер: `python3 -m http.server 8765` в корне, Playwright + Chromium, данные живые с `tt-stack-prod.onrender.com`. Прод-API отдаёт CORS только для `https://www.tastingandtoasting.com`. Поэтому скрипт пропускает ответы прода через `page.route` без изменений и только добавляет заголовок `access-control-allow-origin`. Скрипт: `tools/passport-check/check-golden-master.js`. Он падает, если:
- логотипа в шапке нет, он не загрузился или его перекрывают флажки или крошки;
- в шапке осталось «CAP»;
- флажков не 12;
- есть горизонтальная прокрутка;
- у фото нет подписи источника;
- страница вина не дошла до состояния ready.

Результат: `CHECK PASSED` на 7 страницах задания × 1440/390 (ru). Дополнительно прошли:
- en и he (RTL) для La Chablisienne;
- урожай La Chablisienne 2020;
- винодельня Rabl (en);
- «не найдено» для вина и бутылки.

**Слом-проверка:** из `wine-passport.html` убран `<a class="tt-logo">`. Скрипт выдал `FAIL … logo: missing in header` на всех 12 прогонах страницы вина, итог `CHECK FAILED: 12 page(s)`, страницы винодельни остались ok. Файл вернули, повторный прогон дал `CHECK PASSED`.

Скриншоты: `docs/screenshots/site-passport-golden-master-01/`
- `site-<вино>-1440.png`, `site-<вино>-390.png`: новая страница;
- `gm-<slug>-1440.png`: Golden Master того же вина. GM это статичный снимок десктопа из приложения, на 390 он не перестраивается, поэтому мобильного снимка GM нет;
- `site-winery-la-chablisienne-*`, `site-vintage-la-chablisienne-2020-*`, `site-bottle-scan-notfound-*`, `site-wine-notfound-*`, `site-la-chablisienne-he-*`, `site-la-chablisienne-en-*`, `site-winery-rabl-en-*`.

## Находки, не исправлены (вне задачи)

1. **`/cap/b/:token` (rewrite) грузит скрипты по относительному пути.** `src/i18n/cap-i18n.js` уходит в `/cap/b/src/...` и получает 404. Проверено на проде: `https://www.tastingandtoasting.com/cap/b/abc/src/i18n/cap-i18n.js` → 404. Новые общие файлы шапки подключены по абсолютному пути (`/src/passport/...`, `/assets/tt-logo.svg`), а `cap-i18n.js` оставлен как был. Отдельная задача: перевести его на абсолютный путь или сменить rewrite на redirect, как сделали с `/w/:id`.
2. Прод-API разрешает CORS только для `www.tastingandtoasting.com`. У голого `tastingandtoasting.com` заголовка нет. Если голый домен отдаёт страницы без редиректа на www, паспорта там не загрузятся. Не проверял, на прод не ходил.
3. Живого токена бутылки нет, поэтому `bottle-scan` проверен только на экране «не найдено» (шапка, логотип, 390). Сам `GET /scan` с настоящим токеном не вызывал, чтобы не регистрировать фальшивое сканирование.
